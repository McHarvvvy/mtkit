### 1. 变量命名
- **导出性标识符**：解释“是什么” 或 “做什么” 或 “不做什么”，描述性强且保持简洁
- **局部标识符**：作用域内清晰明义，尽量简短，如
    - 循环变量：`i`, `j`, `k`
    - 字典：`k` 用于索引，`v` 用于值
    - 错误变量用 `err`
    - 上下文变量统一用 `ctx`
- **驼峰命名**：使用 `MixedCaps` 或 `mixedCaps`
- **缩写词全大写**：`HTTP`, `ID`, `URL`（如 `ServeHTTP`, `userID`）

### 2. 包命名
- 小写单个词，无下划线或驼峰：`http`, `time`, `json`
- 简洁、描述性强，避免 `util`, `common`, `base` 等泛化名称
- 包名是导出标识符的一部分：`buf := new(bytes.Buffer)` 而非 `buf := new(bytes.BytesBuffer)`
- 导入顺序：分组管理，标准库、第三方库、本地包之间用空行分隔。

### 3. 接口
- 接口应解释“能做什么”，而不是“是什么”
- 接口类型名以 `i`（私有）或 `I`（公共）开头
- 接口名以 `er` 结尾，或者以所属层级结尾如：`Service`,`Dao`
- **小接口**：接口应尽可能小（1-3 个方法）
- **接受接口，返回结构体**：函数参数用接口，返回值用具体类型

### 4. 函数和方法
- 使用动词或动词短语：`Get`, `Set`, `Parse`, `Validate`
- Getter 不加 `Get` 前缀：`obj.Name()` 而非 `obj.GetName()`
- Setter 使用 `Set` 前缀：`obj.SetName(name)`
- 布尔返回值用 `Is`, `Has`, `Can` 等前缀：`IsValid()`, `HasPrefix()`
- 接收者名称简短一致（1-2字符）：`func (c *Client) Get()` 

### 5. 文件组织
- 使用 snake case，小写单词 + 下划线连接
- 相关功能放在同一文件或包中
- 文件大小适中（通常 < 500 行）；若拆分文件，要有清晰逻辑，保证可读性
- **行长度**：软限制 **120 字符**，在链式调用、结构体字面量等场景可适当超出，以可读性优先

### 6. 错误处理
- **立即检查错误**：不忽略错误返回值
- **向上传播**：在适当层级处理，不过早处理；尽量不适用 try/catch 模式
- **避免 panic**：仅用于不可恢复的程序错误
- **默认工具**：优先使用项目封装的 msserror 包

### 7. 函数设计
#### 参数设计
- **少即是多**：参数数量 ≤ 3 个为佳，超过考虑使用配置结构体
- **上下文优先**：涉及取消或超操作的函数第一个参数应为 `context.Context`
- **避免布尔参数**：枚举类型提高可读性，复杂情形可考虑选项模式
#### 返回值
- **明确性**：返回具体类型而非接口类型
- **错误**：最后一个返回值为 `error`
#### 函数长度
- 保持简短（通常 < 200 行）
- 一个函数做一件事
- 复杂逻辑拆分为辅助函数

### 8. 并发管理
#### Goroutine 管理
- **明确生命周期**：确保 goroutine 能正常退出
- **使用 context 控制**：传递 `context.Context` 实现取消和超时
- **避免泄漏**：确保所有启动的 goroutine 都会结束
#### Channel 使用
- **明确所有权**：发送方负责关闭 channel
- **缓冲大小**：根据实际需求设置，避免默认无缓冲导致阻塞
- **select 使用**：select 可在需要非阻塞行为时使用 default，避免无意义空转
#### 同步原语
- **优先 channel**：用于通信和协调
- **Mutex 保护数据**：用于保护共享状态
- **sync.Once**：用于一次性初始化
- **避免过度同步**：设计无锁或减少锁竞争的方案

### 9. 性能考虑
#### 内存分配
- **预分配切片**：已知大小时使用 `make([]T, 0, capacity)`
- **避免不必要的指针**：小对象（< 64 字节）值传递更高效
- **defer 开销**：性能关键路径避免 defer，普通代码优先可读性
#### 字符串处理
- **使用 strings.Builder**：拼接多个字符串
- **避免 += 循环拼接**：每次都会分配新内存

### 10. 注释和文档
**注释使用中文**
**注释负责解释“为什么”，命名负责解释“是什么”**
#### 包注释
- 描述整个包的功能和定位是什么
- 包暴露接口的主要用法是什么
- **关键技术决策**：如有必要，说明选择这种方案而放弃另一种方案的原因
#### 函数注释
- **必须注释**：所有导出的类型、函数、常量、变量
- **以名称开头**：`// Get 获取...` 而非 `// 该函数获取...`
- **说明用途**：用完整句子说明用途而非实现细节
#### 函数内注释
- **解释为什么**：而非做什么（代码命名本身应该清晰表达做什么）
- **标记待办**：使用 `// TODO(username): description`
- **警告注意事项**：使用 `// 警告:` 或 `// 重要:`
#### 结构体注释
- 【强制】如果有 JSON 序列化需求，加上 json 注解
- 【强制】如果有 SQL 需求，加上 sql 注解
- 【建议】普通字段加上注释，说明用途
